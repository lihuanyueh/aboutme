從手動截圖到自動化月報

跟 Claude 一起把工程顧問案的每月進度報告，從「每月手動截圖＋人工比對公文」磨成一套可重複、可驗證的工作流，最後收斂成一個能套用到其他專案的 skill。

成果類型：自動化工作流 + Skill 2026.07 – 08
適合誰看：常態要交付政府標案／顧問案月報的人；或想了解怎麼跟 Claude 協作，把一次性任務磨成可重複流程的人。
01

痛點說明

  • 原本每月要準備兩份檔案：Word 工作月報＋Excel 工作期程表，兩邊還要手動對齊進度。
  • 工作期程表（甘特圖）是每個月手動截一次 Excel 畫面貼進報告裡——排程一動就要重截一次。
  • 來往公文要跟簽核系統匯出的紀錄手動核對，格式不完全一致，容易重複列或漏列。
  • 進度表、人力時數表、往來公文、當月／次月工作說明——格式固定，但每月的實際內容要重新盤點。
  • 每個月都在做「跟上個月很像、但不能直接複製」的重工，很難交給別人代勞，也很難靠純模板解決。
02

逐步研討

prompt 設計邏輯

  • 第一句 prompt 只問了「需要給你什麼資料才能建立這個工作流」，不是直接要 Claude 產出報告。
  • Claude 在回答之前，先讀懂既有 Word 報告和 Excel 期程表的實際結構，確認章節、表格分別對應什麼內容，而不是憑經驗猜。
  • 把每月要處理的內容拆成三種分開談：原則不變的樣板、可以從資料算出來的內容、只有人才知道的敘述。
Leo 「我要每月定期產出如資料夾中的報告，期程表的內容要自動更新至最新月份，我需要給你什麼資料來建立這個工作流？」
Claude 先讀完兩份範本檔案，拆解出每月會變／不會變的部分，再回頭列出需要的資料清單

五大區塊，各自怎麼更新

月報裡有五個每月都要更新的區塊，更新邏輯各不相同——甘特圖是純資料運算，公文是比對現有紀錄，敘述性內容則要參考上一份報告的寫法：

甘特圖（表一）資料運算

AI 自動把預定進度更新到最新月份；實際進度預設等於預定進度，除非使用者另外回報差異。

圖中的圳名已用「○○」替換，實際客戶／機關資訊不對外公開。

當月工作說明＋次月預定工作承接上月＋比對甘特圖

  • 當月工作：先複製上一份報告「次月預定工作」的內容，再對照甘特圖，檢查本月是否有新啟動的工作項目要補上。
  • 次月工作：依甘特圖裡「次月」對應的工作項目自動填入。

工作人力（表二）依當月工作估算

依當月實際執行的工作項目，對照人力組織的分組與職級去估算工時。姓名部分已在圖中遮蔽。

來往公文（表三）CSV 比對＋校對

使用者提供簽核系統匯出的 CSV，AI 自動辨識欄位、比對既有清單、填入並校對，避免重複列或漏列。下面是示意用的假資料，不是真實公文內容：

序號發文日期發文單位發文字號主旨
12115/6/10○○機關○字第00123號檢送「○○計畫」115年5月工作月報，請查照。
13115/6/12○○機關（未提供）同意本處於○○地設置臨時監測井案，請查照。
14115/6/15○○公司○字第00456號檢送「○○計畫」保險單正本，請查照。

第 13 筆刻意示範沒有文號的情況：這種公文 AI 會依日期與主旨內容自行假設比對邏輯，但不會悄悄套用——而是明確標註「這是我的假設」，請使用者確認後再收進清單。

圖一（計畫組織）是報告裡固定不變的部分，這次沒有調整，直接沿用範本，所以不放在這裡的更新邏輯中。

疊代修正過程

  • 第一輪試跑：進度表只顯示了「預定進度」，沒有同時顯示「實際進度」。
  • 第二輪：使用者回報「圖一（組織圖）壞掉了」——但在 Claude 這邊的預覽工具打開明明正常。
  • 第三輪：使用者手動調整過表格格式後，Claude 整份重新產生蓋掉了調整；公文去重邏輯沒比對日期，誤刪了一筆真實紀錄。
當時「圖一壞掉」「進度沒顯示完整」的實際截圖，之後補上

踩過的坑

  • !肉眼看不出來的結構性錯誤：圖片壞掉的根因不是圖片本身，是自己寫的表格 XML 元素寫入順序不符合 Word 規範，Word 開啟時「修復」，把圖片修掉了。解法不是小心一點，而是每次交付前都跑一次正式的 schema 驗證工具。
  • !去重邏輯只比對文字，沒比對日期：同一份公文可能在系統上出現兩個不同簽核時間，只比對字號跟主旨文字，會誤刪掉真實存在的紀錄。
  • !整份重新產生，蓋掉了使用者的手動調整：使用者在 Word 裡調整過表格格式後，若整份文件重新產生，會把調整蓋掉——改成只讀取並編輯需要異動的段落／表格，其餘完全不碰。

關鍵決策點
1

把截圖改成原生表格＋色塊

沒有這一步，自動化根本無從談起——貼圖沒辦法被程式更新，只能每月手動重截。改成表格之後，資料才能直接從 Excel 算出來、動態上色。

2

導入 XML schema 驗證，作為交付前的硬性關卡

圖片壞掉的根因是表格 XML 元素寫入順序不合規範，肉眼完全看不出來。解法是每次交付前都跑一次正式驗證工具，把「看起來沒問題」升級成「有工具把關」。

3

去重邏輯從「文字相同」改成「文字＋日期都對得上」

同一份公文可能在系統上出現兩個不同簽核時間，只看文字內容會誤刪真實存在的紀錄。

4

資料不全時，先假設再請人驗證，而不是悄悄猜

遇到沒有文號可比對的公文，AI 會依日期、主旨內容自己假設比對邏輯，但不會直接套用——而是明確標註「這是我的假設」，交給使用者確認，把最終判斷權留給人。

03

成果展示

這次協作的三個成果，都是透過對話直接遞送的檔案，沒有公開網址——點卡片可以看更完整的說明。

最直接的改變：原本每月要交付 Word 報告＋Excel 期程表兩份檔案；系統建好之後，期程表已經原生內嵌在 Word 報告的表格裡，現在只要維護、交付一份 Word 報告就好，不用再另外產出一份 Excel 檔案。
04

未來方向

本專案精進

  • 「本月完成項目」可以做成更結構化的輸入介面，減少來回確認。
  • 目前公文清單是由行政同仁協助手動匯出 CSV，如果能直接串接公司的 ERP 系統，這一步就可以再更自動化。
  • 累積更多個月之後，可以回頭把估算邏輯（如人力時數）校準得更準。

延伸應用

  • 任何「Word 報告＋Excel 排程表＋往來文件記錄」三件套的定期報告都適用。
  • 例如：工程履約報告、政府標案進度報告、內部專案週報。
  • skill 已經封裝成通用版本，換專案時不用從零開始。

如果你也想試試看

把自己的定期報告交給 Claude 自動化之前，可以先檢查這幾件事：

  • 先讓 Claude 讀你現有範本的實際結構，不要自己假設它長什麼樣
  • 把「每月會變」跟「原則不變」的部分講清楚，分開處理
  • 第一次先試跑一次，讓格式、邏輯上的問題先浮現出來
  • 敘述性內容（本月實際做了什麼）一定要親自告訴 Claude，不要讓它用預設值去猜
  • 覺得這套流程以後還會用到其他專案，就讓 Claude 幫你收斂成一個 skill

月度交付物說明

工作月報.docx（期程表已內嵌）

工程顧問案專屬的月度交付物（機關與標案全名不對外公開），本篇案例示範的是 115 年 7 月版本。系統建好之後，期程表已經內嵌在報告的表格裡，不用再另外交付一份 Excel 檔案。

運作邏輯
  • 1讀取上月範本結構 — 不假設格式，實際解析段落與表格對應關係
  • 2依甘特圖資料建立色塊表格 — 用原生 Word 表格取代貼圖截圖，期程表不再需要獨立產出
  • 3比對簽核系統匯出的公文清單 — 文字＋日期都對得上才算重複
  • 4跑 OOXML schema 驗證 — 確認在真正的 Word 裡也能正常開啟
這份檔案是這個工程顧問案專屬的交付物，透過對話直接產出給使用者，不是公開網址，這裡用說明取代連結。
