AI 協作案例

個人藏書資料庫升級計畫

把 266 本書從平面 Excel 表格，變成可互動的神經網路視覺化＋Obsidian 知識圖譜——全程用 Claude 協作，不寫任何一行程式碼。

成果類型：HTML 視覺化 + Python 工具 + 知識圖譜 2026.08 266 本書 4 個協作階段
適合誰看：有大量資料想整理視覺化、想讓 AI 處理重複性資料工作、或想把 Excel 資料接上 Obsidian 知識管理系統的人。
01

痛點說明

  • 266 本書全部只存在一份 Excel 表格裡，打開來是一列一列的紀錄，看不出任何書籍之間的關係。
  • 已經有 14 個學習領域的分類，每本書也各自標了 1–5 個關鍵字，但這些結構在平面表格裡完全發揮不出作用——只能眼睛掃，沒辦法「探索」。
  • 想加一本新書或修改關鍵字，只能進 Excel 手動找、手動改，沒有任何快速搜尋或跨領域連結的方式。
  • 想把這份書單拿出去分享或展示，也不知道怎麼呈現才有意思、才讓人看得下去。
02

逐步研討

Phase 01–02：資料清整與欄位設計

  • 原始 Excel 欄位太多、格式不一致，先讓 Claude 協助精簡成 13 個核心欄位（書名、作者、出版社、出版年份、學習領域、關鍵字 1–5、書籍類型、電子書平台）。
  • 14 個學習領域的命名由 Claude 提案，再由 Leo 確認——確保分類粒度適中，既不太細碎也不過於寬泛。
  • 關鍵字策略：每本書限填 5 個，Claude 依書名與領域提議，Leo 逐一確認或修改。
Leo 「我有 266 本書的 Excel，欄位很亂，幫我整理成乾淨的格式。」
Claude 提案精簡欄位結構，並建議統一「電子書 / 實體書」類型標記方式，以利後續自動化處理。
結果比對：原本欄位數量不固定、有空白有合併儲存格；整理後固定 13 欄，每行一本書，欄位含義明確，Python 腳本可直接讀取。

Phase 03：神經網路視覺化

  • 第一個想法是用 SVG 做靜態圖，但 266 個節點用 SVG 渲染效能差——Claude 建議改用 D3.js Canvas 2D 渲染，可以流暢支援 281 個互動節點（1 中心 + 14 領域 + 266 書籍）。
  • 節點配置：書籍節點大小固定，領域節點依書本數量縮放，同領域書籍靠近力學模擬自然聚成群。
  • 互動設計：左側 50 個高頻關鍵字 chip，點一下全圖篩選；點書籍節點，右側滑入常駐詳情面板（書名、作者、出版社、領域、關鍵字）。
Leo 「Continue from where you left off.」（接續上一 session，第一版視覺化只有 120 本）
Claude 發現舊版是早期 SVG 版本，只含部分書籍，決定全部重建——把所有 266 本書的資料嵌入 HTML 作為 inline JS 常數，改用 D3.js v7 force simulation + Canvas 2D 渲染。
結果比對：舊版 SVG 靜態圖，120 本書，無互動；新版 Canvas 動態力導向圖，281 個節點全部上圖，支援平移、縮放、點擊、關鍵字篩選。

Phase 04：Obsidian 知識圖譜串接

  • 目標：Excel 修改後，只要執行一個檔案，Obsidian 的 Markdown 筆記就能自動同步更新。
  • 方案評估：增量同步（只更新變動的行）vs. 全量重建（每次清空再重新生成所有 MD 檔）。
  • 選擇全量重建——增量同步需要追蹤哪些行被改動，技術複雜度高，且有產生殘留舊關鍵字的風險；全量重建每次都能保證資料一致。
  • Vault 結構：書籍/（266 個 MD）+ 領域/（14 個 MD）+ 關鍵字/（999 個 MD）+ 藏書總覽.md，全部用 [[wikilink]] 相互連接，在 Obsidian Graph View 裡形成完整知識網絡。
Leo 「你把 Excel 串接成一個 MD 檔，讓 Obsidian 可以直接讀取做成網狀，然後要怎麼讓我修改 Excel 的同時，MD 也可以修改，如果不行就是給一個執行檔，修改完執行就能串接在一起。」
Leo 「我需要 Windows 執行檔，然後如果我修正關鍵字的話，MD 檔也會一起修正新的連結嗎？舊的就會自己斷開？」
Claude 確認全量重建策略：每次執行都清除舊 MD、從 Excel 重新生成，所以舊關鍵字 wikilink 自動消失、新的自動出現，無需手動管理。產出 .py + .bat（Windows）+ .command（Mac）三個檔案。
結果比對：使用者需要手動管理 Obsidian 筆記（修改多個檔案） → 現在只需修改 Excel，雙擊 .bat，999 個關鍵字節點自動重建。

踩過的坑

  • A 視覺化只顯示 120 本，不是全部 266 本。 原來存在 workspace 的 HTML 是更早期的版本，是另一個 session 產出的舊檔。從對話 .jsonl 取出資料後全部重建，才補齊所有書籍。
  • B pptxgenjs 模組找不到。 環境安全政策封鎖了 npm install，一般裝法行不通。解法：發現 pptxgenjs 已預裝在非標準路徑，改用 NODE_PATH=/usr/local/lib/.../node_modules node make.js 繞過。
  • C Tooltip vs 常駐面板的設計取捨。 一開始做成 hover tooltip，但 266 個節點密集，很容易誤觸、面板閃動。改成「點擊後滑入右側面板，只有按 × 才關閉」的常駐模式，操作感更穩定。

用到的技術

關鍵決策點

1

SVG → D3.js Canvas 渲染

266 本書的 SVG 靜態渲染效能瓶頸明顯；改用 Canvas 2D + force simulation，同樣是純 HTML 單檔、無後端需求，但流暢度從「卡頓」升級為「可互動」。

調整前

SVG 靜態圖，120 本書，節點密集時完全無法互動

調整後

Canvas 動態力導向，281 個節點，支援縮放 / 點擊 / 篩選

2

Tooltip → 常駐右側面板

節點密集環境下，hover tooltip 容易因游標微小偏移而閃爍消失，使用者每次都要重新定位。改成點擊觸發、手動關閉的常駐面板，瀏覽節點時可以放鬆移動游標。

3

Obsidian 同步：增量追蹤 → 全量重建

增量同步需要記錄每行的變更狀態，且修改關鍵字時舊 wikilink 可能殘留。全量重建每次清空再生成，永遠與 Excel 保持一致——執行速度夠快（266 本書約 2 秒），複雜度換簡單度值得。

成果 01 — HTML 視覺化

學習領域神經網路圖

純 HTML 單檔，無後端、無框架依賴，直接用瀏覽器打開即可使用。

功能說明
  1. 1左側 50 個高頻關鍵字 chip——點一下，非相關書籍淡出至 8% 透明度，相關書籍高亮並顯示到領域的連線。
  2. 2點擊任何書籍節點——右側滑入常駐詳情面板（書名、作者、出版社、領域徽章、關鍵字），只有按 × 才關閉。
  3. 3力導向自動排列——同領域書籍自然聚成群，領域節點依書本數量縮放大小。
  4. 4支援滑鼠滾輪縮放和拖曳平移，方便探索密集區域。
